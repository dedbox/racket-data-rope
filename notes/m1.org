** 1. Terminology, and where the legacy system sits
- *Terminology.* The shipped names are dictionary names: =chunk-dict= in =data/rope/core.rkt=, and
  =string-dict= / =bytes-dict= / =vector-dict= in =data/rope/dicts.rkt= (commit =982271a=, "rename
  chunk signatures to chunk dictionaries"). The stale =sig= spellings in =notes/m0.org= are now corrected (ADR-001, ADR-018, ADR-019,
  §3.2 rows 8 and 21, §4's intro) in the pass that added ADR-025, and §1.2 and §1.3 there write
  =length= as =core.rkt= does. The code names above are the ones M1 builds on,
  and a type's runtime constant is named =τ:dict= by convention, e.g. =string-rope:dict=.
- *The legacy system* lives in a separate repository, =/home/eric/work/racket-rope= (branch =dev=),
  and serves only as the oracle for differential content tests and latency comparison (§1.6).
  None of its design is retained: M1 replaces per-type realization of a 45-member interface with
  dictionary passing, and the only lessons worth keeping are the anti-pattern list in
  =notes/overview.org= §4.1.

** 2. What M1 contains
- *One idea.* M1 makes a rope type an ordinary module binding that is *both* a compile-time index
  and a runtime dictionary constant, and generates the user-facing operations from one table. The
  tree code in =core.rkt= gains nothing, which is invariant 11.
| M1 contains                                      | Milestone that owns the rest        |
|--------------------------------------------------+-------------------------------------|
| =define-rope-type=: record + dictionary constant   | newtypes and =#:like= are M5          |
| =define-rope-ops=: the standard-op table           | inline mode and =#:inline= are M3     |
| explicit type arguments at call sites (T0, §2.2) | inference (T2) is M2                |
| =string-rope= and =bytes-rope=, measured limits      | classes and instances are M4        |
| conversions =string->rope= / =rope->string=          | =rope-cast=, debug build, docs are M5 |
| dictionary mode, benchmarked                     | unsafe core and =#:specialize= are M6 |

- M1 ships the *explicit* form, e.g. =(rope-ref string-rope r i)=. That is deliberate: resolution,
  arity checking and error messages are testable against an API whose type is spelled out, so M2
  widens a grammar instead of refactoring every op. P2's "no type argument at call sites" lands in
  M2; T0 stays available forever (§2.2).
- Two measurement obligations attach to M1: §3.2 row 6 (dictionary access within 10% on random
  access) and §3.2 row 12 (re-pin the ceilings under the current harness *before* gating M1/M3).

** 4. The type record (Proposed)
#+begin_src racket
;; data/rope/private/type-stx.rkt
#lang racket/base
(require (for-syntax racket/base))
(provide (for-syntax (all-defined-out)))

(begin-for-syntax
  ;; A rope type: a nominal name, the dictionary it is realized by, and the primitive syntax
  ;; of every chunk-algebra operation (kept so M3 can inline them).
  (struct rope-type (name dict-id primitives) #:transparent)

  ;; Fixed key order: the eight dictionary fields plus chunk?, which the dictionary itself
  ;; does not carry -- ADR-001 places chunk? at the typing layer.
  (define type-keys '(empty length ref slice append width limit merge-limit chunk?))

  ;; Resolution reads the lexical context of the expansion. Standard mechanism: struct
  ;; identifiers, via syntax-local-value. No local-expand, no syntax properties (ADR-003).
  (define (resolve-rope-type stx)
    (define v (syntax-local-value stx (λ () #f)))
    (cond [(rope-type? v) v]
          [else (raise-syntax-error #f "not a rope type" stx)])))
#+end_src

- =chunk?= is stored on the record and never in the dictionary: M5's =rope-cast= needs one
  =chunk?= test on the first leaf, and ADR-011's debug build asserts it. Recording it now avoids a
  breaking change later. The dictionary carries eight fields (ADR-018); the record carries nine keys.
- Nominal identity is the record's =name=, not the dictionary (ADR-004). Two types sharing one
  dictionary are distinct types; M1 rejects mixing them, M5 offers =rope-cast= between them.
- ~rope=?~ and ~rope<?~ style class operations are M4, so the record holds no equality, hashing or
  ordering entry -- invariant 5 and ADR-010.

** 5. =define-rope-type= (Proposed)
#+begin_src racket
;; data/rope/type.rkt
#lang racket/base
(require (for-syntax racket/base syntax/parse data/rope/private/type-stx)
         data/rope/core
         syntax/parse/define)

(provide define-rope-type)

(begin-for-syntax
  (define-syntax-class prim #:description "a primitive operation" (pattern id:id))
  (define-syntax-class nat #:description "a natural number"
    (pattern n:integer #:fail-unless (>= (syntax-e #'n) 0) "negative limit"))
  (define-syntax-class prim-or-lit #:description "a primitive or a literal"
    (pattern (~or id:id lit:literal))))

(define-syntax-parse-rule (define-rope-type τ:id
  #:chunk?       chunk?:prim
  #:empty        empty:prim-or-lit
  #:length       len:prim
  #:ref          ref:prim
  #:slice        slice:prim
  #:append       app:prim
  #:width        [width (~or nat:integer prim)]   ; constant, or a chunk procedure
  #:limit        limit:nat
  #:merge-limit  [merge-limit nat])

  #:fail-when (or (< (syntax-e #'merge-limit) 1)
                  (> (syntax-e #'merge-limit) (syntax-e #'limit)))
          "merge-limit must be between 1 and limit (ADR-019)"

  (begin
    (define τ:dict (make-chunk-dict #:empty empty #:length len #:ref ref
                         #:slice slice #:append app #:width width
                         #:limit limit #:merge-limit merge-limit))
    (define-syntax τ (rope-type 'τ #'τ:dict
                         (list empty len ref slice app width limit merge-limit chunk?)))))
#+end_src

- One binding, two roles: =τ:dict= is the runtime dictionary, =τ= is a syntax binding carrying the
  index. Both are exported by =(provide (all-defined-out))=, so a type is renamed and imported by
  the module system like any name. Nominal identity is binding identity (§2.2), so the legacy
  =rope:string= naming convention is gone: =string-rope= coexists with =string=.
- The record's nine primitives follow the =type-keys= order, =chunk?= last (§4), so the
  eight dictionary fields keep indices 0 through 7, and slot 8 holds the predicate that
  only exists at compile time -- an index needs no shifting between them.
- =merge-limit <= limit= is a structural invariant (=rope-valid?=, =core.rkt:442=), so it is checked
  at expansion time, never at runtime.
- A constant =#:width= is wrapped by =make-chunk-dict= (=core.rkt:100=). The record keeps the
  *original* syntax so M3 can inline =(* 1 (string-length c))= instead of calling the wrapper.
- =#:instances= (the convenience clause of §2.2) is deliberately absent: instances are M4.

** 6. The standard-op table (ADR-006)
One table replaces the legacy's 45 hand-written members. A signature carries arity checking, and
in M2 it drives result typing.

#+begin_src racket
(define-rope-ops
  ;; name            core fn                 signature                  dict?    notes
  [rope-empty?      core:rope-empty?        (τ -> boolean)             #:none]
  [rope-length      core:rope-length        (τ -> fixnum)              #:none]
  [rope-width       core:rope-width         (τ -> fixnum)              #:none]
  [rope-height      core:rope-height        (τ -> fixnum)              #:none]
  [rope-chunks      core:rope-chunks        (τ -> list)                #:none]
  [rope-fold-chunks core:rope-fold-chunks   (τ proc α τ -> α)          #:none]
  [rope-valid?      core:rope-valid?        (τ -> boolean)             #:dict]
  [rope-ref         core:rope-ref           (τ fixnum -> elem)         #:dict]
  [rope-split       core:rope-split         (τ fixnum -> τ τ)          #:dict]
  [rope-slice       core:rope-slice         (τ fixnum fixnum -> τ)     #:dict]
  [rope-splice      core:rope-splice        (τ fixnum fixnum τ -> τ)   #:dict]
  [rope-concat      core:rope-concat        (τ τ -> τ)                 #:dict]
  [rope-append      core:rope-concat        (τ τ ... -> τ)             #:dict #:fold]
  [chunk-length     core:chunk-dict-length  (chunk -> fixnum)          #:dict-only]
  [chunk-ref        core:chunk-dict-ref     (chunk fixnum -> elem)     #:dict-only])
#+end_src

- =#:none= rows are the thin wrappers ADR-006 exists to remove: they expand to plain core calls with
  no dictionary.
- =#:dict-only= rows expose the chunk algebra itself for hand-written hot loops.
- =#:fold= turns a binary core function into a variadic op (a left fold over the tail).
- Structural operations stay plain functions as well (§2.5); the type-dependent first-class form is
  =(rope-ref/τ string-rope)=, a row flag rather than hand-written code. M1 ships no such flag -- it
  arrives with =define-rope-op= at M3, which is the only consumer (§13 row 2).
- Slicing keeps Racket's convention, =slice chunk start end= (ADR-013).

** 7. One row, one macro (Proposed)
#+begin_src racket
(begin-for-syntax
  ;; τ marks a rope argument; concrete names (fixnum, elem, α) are unchecked in M1.
  (define (rope-arg? spec) (eq? (syntax-e spec) 'τ)))

(define-syntax-parse-rule (define-rope-op name:id core:id (arg ...) result:list #:dict)
  #:with (pat ...) (map arg->pattern (syntax->list #'(arg ...)))
  #:with (a ...)   (map arg->use    (syntax->list #'(arg ...)))
  (define-syntax-parse-rule (name τ:id pat ...)
    #:do [(define tp (resolve-rope-type #'τ))
          (for ([arg (in-list (syntax->list #'(arg ...)))])
            (when (rope-arg? arg) (check-rope 'name tp)))]
    #:with dict (rope-type-dict-id tp)
    (core dict a ...)))
#+end_src

- =check-rope= asserts each argument is itself a type id and that every τ argument agrees. The
  message is in domain terms, never in representation terms:
#+begin_src text
rope-concat: ropes of different types
  a : string-rope
  b : bytes-rope
#+end_src
- Arity errors come free from the pattern arity of =syntax/parse=.
- The leading type argument is parsed by *one shared syntax class*, so M2 widens it to inference
  without touching any row, and the explicit form stays valid forever (T0, §2.2). ⟦verify⟧ that one
  syntax class can accept both a type id now and an inferred position later.
- Nothing in this layer infers a type from a binding: static info on bindings is M2, and §3.3 Q16
  fixes the grammar then. Widen it by adding rows, not by expansion tricks (ADR-003).

** 8. The =τ.op= accessor -- built in M1, used at M3 (Proposed)
#+begin_src racket
(begin-for-syntax
  ;; τ.op resolves τ statically: a type id gives the primitive as syntax; a variable holding a
  ;; dictionary gives the runtime accessor. One text, two expansions (ADR-005).
  (define-syntax-parse-rule (τ.op τ:id key:id . rest)
    #:do [(define v (syntax-local-value #'τ (λ () #f)))]
    #:with prim (cond [(rope-type? v) (rope-type-primitive v (syntax-e #'key))]
                      [else (datum->syntax #'τ (list (dict-accessor (syntax-e #'key)) #'τ))])
    (prim . rest)))
#+end_src

- Table rows write =(core dict a ...)= directly, so M1 does not use the accessor; =define-rope-op=
  (M3) does. Building it now keeps ADR-005's promise honest: *a failing gate becomes one keyword*,
  not a rewrite.
- The accessible key set is exactly =type-keys=, which is why no substitution machinery is needed --
  this is the small replacement for the legacy =star-substitute= and =τ.key= binding machinery.
- ⟦verify⟧ two risks named in =notes/overview.org= §4: =syntax-local-value= must see the *caller's*
  lexical context (pass the op's syntax down, do not rewalk), and the accessor must work inside
  nested macros and =for= bodies.
- =#:specialize= (the module-level lift, §3.3 Q20) is M6, not M1.

** 9. The shipped types
#+begin_src racket
;; data/rope/string.rkt
#lang racket/base
(require data/rope/type data/rope/ops data/rope/core)
(provide (all-defined-out))

(define-rope-type string-rope
  #:chunk? string? #:empty "" #:length string-length #:ref string-ref
  #:slice substring #:append string-append #:width 1
  #:limit 512 #:merge-limit 64)          ; measured, §3.2 row 8

(define (string->rope s) (chunk->rope string-rope:dict s))
(define (rope->string ρ) (rope->source-in string-rope:dict ρ))
#+end_src

- =bytes-rope= mirrors it with =#:limit 2048 #:merge-limit 256= (=limit/8=; typing p50 486 ns /
  clean p99 928 ns at 100 K elements and 399 / 1008 ns at 10 MB, §3.2 row 8). Per §3.3 Q18 that
  byte shape is the pipeline's text type: byte positions *are* element indices, and =width= stays
  constant 1.
- Vector and token ropes stay in the benchmark until the pipeline type ships (ADR-018, §3.2 row 21:
  =limit 128, merge-limit 16=). A second token shape, =limit 64 merge-limit 8= or
  =limit 256 merge-limit 32=, is a distinct type via ADR-004's =#:like= -- which is M5.
- =data/rope/dicts.rkt= shrinks: its three dictionaries are superseded by the type modules'
  constants. Keep only the generic flatten helper (=rope->source-in=, driven by a dictionary) there.
  Two dictionary constants for one chunk representation would break coherence (invariant 8).
  =vector-dict= now declares =#:merge-limit 16= (=limit/8=), matching §3.2 row 21 rather than the
  unmeasured default.
- =data/rope.rkt= becomes the collector: re-export the op macros plus =string-rope= and its
  conversions, so =(require data/rope)= covers the common case and =data/rope/bytes= is opt-in.
